## 3. 口径（三条硬要求 + 三条本轮新增）

**(1) 四桶平铺相加。** 用户 2026-09-14 已裁定："不要钱，只要 token 数"。
> ⚠️ **必须再次知情**：平铺相加 ≈ **99.8% 是 `cache_read`**，所以这个数在量的其实是
> **"同一段上下文被重复读了多少遍"**，不是"新消耗了多少内容"。今天的实测值 **165M/天**
> 会让顶栏显示 `全部 165M`。**这是设计，不是 bug**（用户此前已明确知情并接受）；
> 若要"体感更准"的数，应改成只算 `input + output`（**这是另一个口径，需用户点头**）。

**(2) 只算"今天"**（用户 2026-09-16 裁定）。
- "今天" = **本地时区（UTC+8）的日历日**；转录里 `timestamp` 是 **UTC**（`…Z`），必须换算。
- 边界必须写测试：`23:59:59` 属今天、次日 `00:00:00` 不属。
- **跨零点自动归零**：日期一变，账本清零 + 所有 offset 归零重扫（不重扫就没有新一天的数据）。

**(3) ⭐ 按 `message.id` 归组，组内只算一行（2026-09-16 实测更正，原写的是"按 uuid 去重"）。**
- **一次 API 响应会写成多行**（thinking / text / tool_use 各一行），**每行 uuid 都不同**、
  `message.id` 相同、`usage` 基本一样。按行累加 = 同一次调用算多遍：
  实测今天 **2245 行只对应 965 个 `message.id`**，按行累加 403.2M、按组取一行 **175.8M**，
  **虚高 2.29 倍**。`uuid` 去重救不了它（那几行的 uuid 本来就不同）。
- 组内取 **`timestamp` 最大**的那一行：实测 19,799 组里最后一行的 `output_tokens`
  **100% 是组内最大值**（零反例）——中途的行写着 `output_tokens: 0`。
  注意 394 组**文件顺序与时间戳顺序不一致**，所以判据是"时间戳最大"而非"最后读到的"。
- 组内的行是**陆续**写进来的 ⇒ 新行到来时要**把旧的贡献减掉**再记新的（只加不减就是虚高那版）。
- 没有 `message.id` 的行退回用 `uuid` 当键。
- 变异验证：退回按 uuid 去重 → 红；替换时忘了减 → 红。

**(4) 【新增】按行取 `cwd` 归属项目。** 79/163 份文件跨多个 cwd（实测），
所以"会话 → 项目"是**多对多**，会话行上**没有**唯一的项目累计可显示。

**(5) 【新增】`mtime` 预筛**：只扫 `mtime ≥ 今天0点` 的文件。
> 依据：文件是**追加写**的，今天没被写过的文件不可能含今天的行。
> 代价：8.2 MB vs 325 MB。**这条必须写成可测的断言**（造一个"mtime 是昨天但内容含今天 timestamp"
> 的夹具 —— 那种情况只可能出现在时间被改过的机器上，属防御性测试）。

**(6) 【新增】只读、零网络、不写任何状态文件**（本仓承重约束，见 spec §3）。

## 4. 界面形态

### 4.1 token

```
● claude 会话 · 2 个 · 全部 165M          ← 顶栏：全机今日总量（需求 B）
────────────────────────────────────────
▍web-lab             3.4M   工作中   02:41   ← 行尾：该会话今日量
上下文 91%                        子代理 2
────────────────────────────────────────
▍claude-hud         72.0M   完成    02:13
上下文 68%
```

- 数字格式 **K/M 缩写**（用户 2026-09-16 裁定）：`12.8M` / `980K` / `0`
- 摆放位置：会话名之后、右组之前（左对齐段），**不参与右缘基准**

> ⚠️ **一处与用户选择的偏离，需确认**：用户选的是"行尾 = **所属项目的累计**"，
> 但实测 79/163 份转录跨多个 `cwd` ⇒ **没有唯一的"所属项目"**。
> 本计划按"**行尾 = 该会话今日量**"落地（有唯一解），"各项目"那组数**留到 v1 出来后看着定**
> （它本质是个列表，而挂件只有几行位置）。**若用户坚持行尾显示项目数，需要先定"跨项目会话算哪个"**。

### 4.2 子代理连线（∟）

```
▍web-lab                 工作中   02:41
                                 │
上下文 91%              └────┤ 子代理 2
```

**几何（全部以内容坐标为准，可单测）**：
- **竖段**：x = 状态词的水平中点；从第一行 ink **下缘 +2pt** 起，垂到第二行 ink 的**垂直中点**。
- **横段**：从竖段底端**向右**到「子代理 N」的**左缘 −2pt**。
- **颜色** = 状态色（与「工作中」同色，肉眼即知"这条线说的是它"）；线宽 **1pt**。
- **绘制条件**：`subagent_count > 0` 就画。
  > ✅ **用户 2026-09-16 裁定：只要有子代理在跑就画**（不是"只在该会话被顶成工作中时"才画）。
  > 理由（实现者的建议被采纳）：后者会让折线忽隐忽现 —— 主代理自己一开始干活、状态本来
  > 就是"工作中"，折线就会消失，而"有子代理在干活"这个事实没变。
- **实现**：`painter().line_segment()` 两段（与 `paint_right` 同一套"自己算坐标"的路子），
  因为 egui 没有"折线"原语；坐标必须能被单测读到（`Shape::LineSegment` 的 `points`）。

## 6. 已知坑（照抄本仓历史，别重踩）

1. **测量会污染自己的输入** —— 打印转录片段会让那串文字进我自己的转录；今天刚因此造出 4 个幽灵代理。
   凡"从语料里取判据"的测试，**夹具必须取自真机、且验证夹具本身合法**。
2. **`add_space` 与隐式份量** —— 加 token 数字会改变第一行宽度 ⇒ 会动 `name_budget`。
   **别用 `ui.label` 顺序排**（会引入隐式间距，第三轮刚把三处消掉）。
3. **右缘基准不许被破坏** —— 行尾数字**不参与**右组布局；改完必须跑
   `the_state_word_and_timer_are_flush_with_the_right_edge`。
4. **挂件绝不写状态文件**（Ruling #6）—— token 账本只在内存里。
5. **改完要重出 release，而运行中的 exe 锁文件** —— 每次都先杀挂件（M5 再解）。
6. **`cargo test` 的 `run_frame_sized` 高度** —— 测多会话时别用默认 260pt，会被静默裁。
7. **时间换算**：转录 timestamp 是 UTC、机器是 UTC+8；写测试时别用"当前时间 +/- n 小时"当夹具，
   要用**固定字符串**。
